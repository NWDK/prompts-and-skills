# Methods

Write-ups of how something was done, where the value is the reasoning, not
a file you install.

A method isn't a skill or a template: nothing to copy into `skills/`,
nothing to paste into a settings box. It changes how you do the thing, or
it doesn't.

Most exist because a system I built was less transferable than what I
learned building it.

## Adding one

- **Lead with what you found, not what you built.** An interesting
  architecture is a skill; a thing that turned out to be true is a method.
- **Say how you know.** Measured, counted, and noticed are different
  claims; only one is a statistic.
- **Scope the finding to what you saw.** A true statement about one tool,
  stated as true of all of them, goes false without anyone editing it.
- **No configuration.** Needing setup makes it a skill.
