# Video Frames

Picks and extracts the frames that matter from a **local** video, labelled with what was being said, so a model can see what happened on screen. Claude takes images, not video, so this is the step that decides which frames are worth paying for.

It has no network path. Driven by [`skills/video-review/`](../../skills/video-review/), which carries the judgement; the reasoning behind each default is in its [DECISIONS.md](../../skills/video-review/DECISIONS.md).

## Known limits

- Local files only.
- Very small text edits fall below the visual threshold. Cues catch anything said out loud.
- ffmpeg's scene filter is built for hard cuts and barely fires on gradual change, so on much screen content the uniform top-up and deduplication do the real work.
- Cue timing inherits whisper's drift of about half a second. Frames carry their real `ffprobe` timestamp, so a mis-timed cue shows on inspection.
- `--effort large` and `average` behave the same on recordings under about ten minutes at the default cap. The dial matters on long recordings.
- The token estimate is an upper bound. Spend comes in under it whenever the screen sits still.
- JPEG output only, at `-q:v 2`: fine for UI, not for photographic detail.

## Use

```bash
# Cost first. Writes nothing; shows all three effort tiers.
python3 tools/video-frames/extract.py probe walkthrough.mp4

# Frames and manifest, labelled with the transcript (.srt or whisper .json)
python3 tools/video-frames/extract.py extract walkthrough.mp4 \
  --out walkthrough-frames --transcript walkthrough.srt

  --cues 12.5,48.0 --marker screenshot   # pin moments: timestamps, or a spoken word
  --effort small | average | large        # how hard to sweep visually (default average)
  --start 45 --end 60                     # zoom in on one stretch
  --append --cues 31.5                    # fetch one missed moment, keep the rest
  --refine                                # sample halfway between existing frames

# Which frame supports which finding? Run before reading any frames.
python3 tools/video-frames/extract.py map walkthrough-frames \
  --findings "D1=71.8,D2=95.6,V1=129.0"
```

`map` keeps a citing document affordable: on a real 17-minute walkthrough, 28 images covered all 41 findings out of 96 extracted ([numbers](../../skills/video-review/DECISIONS.md#9-the-first-real-run)). It also flags that **a filename is the capture time, not the finding time**: a shared image was taken when the screen last changed.

## How frames are picked

In a screen recording, visual change and importance come apart: scrolling changes every pixel and means nothing, while "this bit is broken" over a still screen changes nothing and matters most. So there are two signals:

- **Cues**: timestamps from `--cues`, or a word spoken aloud via `--marker`. They get reserved budget and survive deduplication.
- **Fill**: ffmpeg scene detection plus uniform sampling, then deduplicated. It catches anything done silently.

The frame budget is a ceiling, not a quota: a 20-second static screen yields one frame. `--effort` scales the sweep and its ceiling (35 / 100 / 200 frames by default) but **never drops cues**; if cues exceed the budget, the ceiling rises to fit them. `--max-frames` overrides every tier.

`--append` and `--refine` add to an existing manifest, so frames already read are never re-sent, and a refine pass that finds nothing new costs nothing.

**"The same picture"** means few pixels changed, compared at 64x64 in RGB. A perceptual hash scored visibly different UI frames as identical, and greyscale under-read a page change fourfold ([why](../../skills/video-review/DECISIONS.md)).

| | Measured |
|---|---|
| Noise floor, static screen | 0.000% synthetic, 0.024–0.098% real footage |
| Small toast, 360x50 on 1600x900 | 2.20% |
| Dialog, 600x300 | 14.5% |
| Full page navigation | 90.6% |
| **Default threshold** (`--dedup-change`) | **0.5%** |

Recalibrate on very different footage: heavy compression raises the noise floor.

## Gotchas

- **`--marker` cues are rewound 1 second** (`--cue-offset`), because what's described is already on screen before the sentence ends. `--cues` and `--refine` are absolute; a caller deriving cues from a transcript subtracts the offset itself.
- **macOS recording filenames have a narrow no-break space (U+202F)** before "pm", so a typed path fails. Glob it: `ls ~/Desktop/*2.23.13*.mov`.
- **Pick a marker word you wouldn't say by accident.** Whisper mishears.
- **One `--out` directory per recording.** A fresh run clears frames it recorded there before, and `--append` refuses a directory that holds a different recording. `walkthrough-frames` beside `walkthrough.mp4` is the convention; `/tmp` loses the frames a report cites.
- **The output directory is sensitive**: stills of whatever was on screen. Keep only the frames `map` cites.
- **The default long edge, 1568px, is Claude's native tier maximum.** Raise it to read small text, at about three times the tokens, and stay at or under 2000px for requests with more than 20 images ([COMPATIBILITY.md](../../skills/video-review/COMPATIBILITY.md)). On another provider, keep the frame selection and re-derive the resolution; frame counts and the threshold are provider-neutral.
- **`--scene-threshold` defaults to 0.2**, lower than a film default, because a modal opening moves far fewer pixels than a hard cut.
- **The manifest is the contract.** Entries can share one `file` (`shares_image_with`); send each image once. Cost follows `distinct_images`, not entry count.
